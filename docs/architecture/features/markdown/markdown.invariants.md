# Markdown invariants

Rules that always hold for the Markdown feature. Format: `- **[area]**: rule (Learned from: source, date)`. To retire one, delete it and say why in the commit or an ADR. Whole-app rules are in [architecture invariants](../../invariants.md). The [overview](markdown.overview.md) is the entry point of this folder.
- **[tables]**: Table rows remain rows by cells and styled runs until layout. Wrapping preserves roles, separators, borders, and aligned empty cells. A table uses its natural column widths when they fit the viewer. An oversized table assigns content widths in proportion to natural widths, then distributes remaining cells by descending fractional remainder and lower column index on ties. (Learned from: story markdown-table-fit, 2026-11-09)

## Markdown viewer

- **[colors]**: A Markdown run holds an `MdRole`, never a color. `MarkdownRunColor` in `far2l/src/ViewerPrinter.cpp` calls `MdRunColor` in `far2l/src/markdown/`. That function resolves the role at draw time from the user file, the fork table of defaults, or a far palette entry. The background is always the viewer text background. See [ADR-004](../../decisions/adr-004-palette-roles.md). (Learned from: story markdown-preview-fixes, owner ruling, 2026-11-05; story markdown-preview-reading, 2026-11-05; story markdown-palette, 2026-11-06)
- **[colors]**: The contrast rule is all or none. Each RGB default needs 3:1 or more against the real viewer background, or every default uses today's palette entry. A cached verdict is keyed on the viewer background, so a theme change recomputes it. (Learned from: story markdown-palette, T3 review, 2026-11-06)
- **[colors]**: A user color comes from `settings/markdown-colors.ini`, section `[markdown]`. far2l reads it and never writes it, and a bad value leaves the role default. Validate the value syntax before `ExprToFarColor`: it returns 0 for a bad value and for a valid black. (Learned from: story markdown-palette, T3, 2026-11-06)
- **[colors]**: Pass a 64-bit real color to `SetColor`. `SetFarColor` takes a palette index, and a real color cut to 16 bits gave black and red blocks. (Learned from: story markdown-preview-fixes, close-out ruling 1, 2026-11-05)
- **[colors]**: A far attribute holds a 24-bit color as `0xBBGGRR` (`COMPOSE_RGB`), and the fork writes colors as `0xRRGGBB`. Only `TrueForeColor` in `far2l/src/markdown/MdPalette.cpp` puts a written color into an attribute. The low attribute bits of an RGB color hold a 16-color index, not a 256-color index. Cell `ForeTC` values in tests are also in `0xBBGGRR` order. A color test uses a value with unequal red and blue, because a swap does not change other values. (Learned from: story markdown-palette, owner check in Ghostty, 2026-11-06)
- **[colors]**: The Colorer look is a resolver step between the user file and the fork table. The plugin answers a ten-name list with a foreground and a style word. A style of bit 4 sets the underline. The core asks with a count-0 probe per draw, and fetches once per scheme generation. The plugin never creates `FarEditorSet`. See [ADR-009](../../decisions/adr-009-colorer-look-step.md). (Learned from: story markdown-colorer-look, 2026-11-07)
- **[colors]**: The Colorer batch contrast verdict is keyed on (viewer background, scheme generation). A theme change and a scheme change both recompute it. An absent region (`fore` 0) falls through to the fork default of its role, and is not a contrast failure. (Learned from: story markdown-colorer-look, T4 review, 2026-11-07)
- **[colors]**: A code-block row paints the block tint as its background, to the right edge and past the text. The tint blends one eighth of the code role's resolved foreground into the viewer background. The gate is true color and 3:1 on (code foreground, tint); one verdict is cached on (viewer background, code color). The printer paints each row in one write pass: runs first, then the tinted tail. `--norgb` gates the tint off. (Learned from: story markdown-code-tint, 2026-11-07)
- **[draw]**: `Console::Text` drops `COMMON_LVB_UNDERSCORE` for one-cell characters. `MarkdownPrinter::Print` records the column span of every underlined run and re-applies the bit with one `GetText`/`PutText` pair per row, after `ApplyColorRanges`. A row with no underlined run costs nothing. (Learned from: story markdown-colorer-look, T5, 2026-11-07)
- **[scroll]**: Markdown mode scrolls by `m_md_top`, an index into `MarkdownDoc::Lines()`. The `nFilePos` of the lines never decreases down the document, and a row that replaces a fence takes the fence offset. See [ADR-003](../../decisions/adr-003-line-index-scrolling.md). (Learned from: story markdown-preview-reading, 2026-11-05)
- **[scroll]**: Markdown keys act only when `MarkdownView()` is true (Markdown on, hex off), so hex mode keeps its own keys. (Learned from: story markdown-preview-reading, task 1 review, 2026-11-05)
- **[layout]**: Word wrap soft-wraps the text, quote, list and table cell rows. Fences, horizontal rules and mermaid art rows keep one row per row and scroll. `MdLine.wrap` carries the mark; the split runs after the layout, in `MarkdownDoc::Render`. (Learned from: story markdown-horizontal-scroll, owner rulings, 2026-11-09)
- **[layout]**: A blank row is one row, and a wrapped row has no trailing spaces. A list continuation starts at the lead indent of its item. (Learned from: story markdown-horizontal-scroll, owner ruling, 2026-11-09)
- **[scroll]**: In Markdown mode, Right, Left, Home and End move `LeftPos` in both wrap modes. The arrow markers overlay the first and last text column. F2 and Shift-F2 re-render at the current width. (Learned from: story markdown-horizontal-scroll, 2026-11-09)
- **[cache]**: `MarkdownDoc::Invalidate` drops the render, the mermaid art cache and the code-block tint cache. It keeps the token cache and the Colorer look cache, which do not depend on the width. (Learned from: story markdown-horizontal-scroll, task 2 review, 2026-11-09)
- **[cache]**: The position cache `Param[3]` of a viewer stores only a deviation from the open rule. The rule is read once at open (`m_md_rule`) and both save sites use it. See [ADR-007](../../decisions/adr-007-markdown-default-on.md). (Learned from: story markdown-default-on, final review, 2026-11-06)

## Diagrams

- **[mermaid]**: Every `AsciiMermaid::Render` call runs under a wall-clock deadline (2 s, `FAR2L_MD_DEADLINE_MS` overrides), a 1 MB JS stack and a 128 MB memory limit. The limit is set once on the one shared runtime (`build_engine`), so the bundle and all fences share it until a timeout frees the runtime. The next call builds it again. (Learned from: story markdown-preview-fixes, final review, 2026-11-05; story markdown-ascii-diagrams, task 2 review, 2026-11-06)
- **[mermaid]**: Diagram text is untrusted. It runs in a quickjs context with no `std` or `os` module and no DOM (the vendored quickjs builds the core only). (Learned from: story markdown-preview-fixes, hostile SVG review, 2026-11-05)
- **[mermaid]**: A fence that cannot be drawn keeps its source as code rows and gets the hint row. It never stops the viewer. (Learned from: story markdown-preview-fixes, spec, 2026-11-05; story markdown-ascii-diagrams, 2026-11-06)
- **[bundle]**: `far2l/bootstrap/mermaid-ascii.js` is built by `far2l/bootstrap/mermaid-ascii/build.sh` and committed. It is at most 300 KB and has no `elkjs`. Run `sh testing/markdown/ascii-golden.sh` after a rebuild. The far2l build never needs Node. (Learned from: story markdown-ascii-diagrams, gate, 2026-11-06)
- **[bundle]**: Golden files come from the `beautiful-mermaid` package in Node, never from the bundle. (Learned from: story markdown-ascii-diagrams, T4 for `A-->B`, 2026-11-06)

## Browser view

- **[browser]**: `far2l/bootstrap/md-open.sh` treats the Markdown file as untrusted. The text goes into the page as escaped data (`\` first, then `</` and `<!--`) and raw HTML shows as text. Mermaid runs with `securityLevel:'strict'`. The page has a `Content-Security-Policy` that allows inline scripts, scripts from all of `https://cdn.jsdelivr.net`, and local images only. Only the page script pins the mermaid URL (`MERMAID_URL`) and its `integrity` hash (`MERMAID_SRI`). The text shows before the CDN script loads. (Learned from: story markdown-browser-view, first final review, 2026-11-06)
- **[browser]**: The printed Alt-F3 command leaves `!.!` unquoted, because far2l escapes the file name. (Learned from: story markdown-browser-view, first final review, 2026-11-06)
- **[browser]**: No script edits `config.ini`. far2l rewrites it on exit. The owner adds the File associations entry by hand. (Learned from: story markdown-browser-view, gate, 2026-11-06)
